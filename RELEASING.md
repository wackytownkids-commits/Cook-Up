# Releasing Cookup

Cookup ships auto-updates via `electron-updater` against a public GitHub
release. Once you've created the GitHub repo and set `build.publish.owner`
and `build.publish.repo` in `package.json`, every release is a three-step
flow.

## One-time setup

1. Create a GitHub repo for Cookup (e.g. `your-handle/cookup`).
2. In `package.json` under `build.publish`, replace `OWNER_PLACEHOLDER` and
   `REPO_PLACEHOLDER` with the repo owner and name.
3. Generate a GitHub Personal Access Token with `repo` scope and export it
   in your shell as `GH_TOKEN` (electron-builder reads it for publishing).
   - Windows (PowerShell): `$env:GH_TOKEN = "ghp_xxx"`
   - macOS / Linux: `export GH_TOKEN=ghp_xxx`
4. `git init`, commit, push to the new repo.

## Shipping a release

```bash
# 1. Bump the version
npm version patch    # or: minor / major

# 2. Push commit + tag
git push && git push --tags

# 3. Build + publish to GitHub Releases
npm run dist:win -- --publish always   # Windows installer
npm run dist:mac -- --publish always   # macOS DMG (run on a Mac)
```

`electron-builder` uploads the installer plus `latest.yml` (Windows) or
`latest-mac.yml` (macOS) to a draft GitHub Release matching the tag.
Open the release on GitHub and click **Publish release** when you're
ready for users to receive it.

## How users get updates

Installed copies of Cookup check `latest.yml` on launch and download new
builds in the background. When the download finishes, a toast appears
in the app: **"Update ready - restart to install"**. The user clicks
**Restart & install** when they want it; we never auto-restart.

There is also a manual **Check for updates** button in Settings.

## Notes

- Updates only fire in the packaged build (`app.isPackaged`), so running
  `npm start` in dev never triggers them.
- **Windows icon cache:** if a release ships an updated icon and users still
  see the old one on the desktop shortcut, taskbar, or alt-tab after they
  upgrade, that's the Windows icon cache, not a build problem. Tell them to
  open `cmd.exe` and run:
  ```
  ie4uinit.exe -show
  ```
  (Or sign out and back in.) That flushes `%localappdata%\IconCache.db` and
  Windows re-reads the icon from the .exe.
- Logs from electron-updater are written to the app's log directory
  (via `electron-log`). On Windows that's
  `%APPDATA%\Cookup\logs\main.log`.
- The bundled Python runtime (`resources/python-runtime/`) is part of
  every release - it's regenerated by `npm run bundle:python:win` (or
  `:mac`) before electron-builder runs, so make sure that step is fresh
  before you publish.
